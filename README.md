# ams — agent managed services

A rootless supervisor core for an **agent managed runtime**: the agent launches
services it declared itself, keeps them as direct children, reads their
stdout/stderr inline, and decides per warning/error whether to **suppress** or
**fix**. No Docker, no per-service systemd units, no root.

```
systemd (keeps the harness alive, Delegate=yes)
└── harness  (unprivileged user, PR_SET_CHILD_SUBREAPER, the agent loop lives here)
    ├── registry / auth  (Layer 0, fixed ports 20100/20101)
    ├── caddy            (the gateway, an ams service like any other)
    └── kvservice / timeservice / …   (translated from the api monorepo)
```

On top of the core there is now a **platform layer** (`src/ams/platform/`): it
mirrors a git repo, translates `service.yaml` manifests into declarations,
provisions and stages each service on a reflink store, renders the Caddy
gateway, creates registry identities and gates on health — all from a one-shot
process on a 60 s timer. `docs/platform.md` is the end-to-end story.

## What you get

- **Isolation without privileges.** Each service runs in its own user namespace
  mapped through `newuidmap`/`newgidmap` into the harness's `/etc/subuid` block,
  with zero capabilities and `no_new_privs`. Limits (`memory.max`,
  `memory.swap.max=0`, `cpu.max`, `pids.max`) are written to a delegated
  cgroup v2 subtree; `cgroup.kill` takes down the whole tree atomically.
- **Logs are fds, not journald.** Lines are tagged `[svc:stream]`, classified
  by severity and routed through an explicit `DecisionPolicy` → `Escalation`
  interface. `--policy platform` adds dedupe-by-cause, a post-sync health gate
  and Caddy-specific rules on top of the default.
- **Dependency isolation that shares disk.** Per-service environments (uv /
  venv / pnpm / bun) live on an XFS `reflink=1` volume together with the
  caches. Measured: a second copy of a 17 MiB tree cost 0.01 MiB.
- **Declarations, not unit files.** One `service.toml` per service
  (start argv, workdir, env, secret *names*, ports, runtime, health, graceful
  stop, limits, restart policy, `depends_on`) — generated by the agent or by
  the manifest translator. See `docs/service-declaration.md`.
- **Write-only secrets.** `ams secret set <id> NAME` reads a value from stdin,
  stores it 0600 harness-owned and injects it at spawn. Nothing prints it back,
  and the harness uid is not mapped into a service namespace, so a service
  genuinely cannot read it off disk.
- **Per-service control.** A 0600 unix socket served from the supervisor's own
  selector loop: `ams ctl reload|start|stop|restart|kill <id>`. A declaration
  change no longer needs a unit restart.

Verified end to end: a real RS256 M2M token minted by the replica registry for
`timeservice` and accepted by `kvservice` through Caddy (204/200), where
anonymous gets 401 and a tampered signature gets 401. Every number above is
n=1 on a page-cache-contaminated host — they are observations, not planning
constants.

Full-fleet bring-up numbers land in `.claude/state/platform-fleet.md`, which
was **still a skeleton with unfilled tables** when this README was written —
treat it, not this section, as the source for fleet-scale figures. What is
already settled from that work: 2 GB and one vCPU cannot hold all 21 services,
so `deploy/ams-platform-sync.service` drives an explicit `--only` list, and
`oss` and `secretsservice` are excluded because neither can start without a
real credential.

|---|---|
| `src/ams/schema.py` | declaration → frozen dataclasses, validation, `depends_on` |

| `src/ams/decision.py`, `events.py` | the suppress-or-fix boundary |

| `src/ams/cli.py` | `ams run/provision/validate/ctl/check-host/secret/platform` |

## Host requirements

Ubuntu 24.04 (or any Linux with cgroup v2 + shadow `uidmap`). `deploy/install-host.sh`
creates the `harness` user, installs the AppArmor profile that grants `userns`
to the harness interpreter (24.04 restricts unprivileged user namespaces),
mounts the XFS reflink store and installs the pinned static Caddy binary.

## Operator quickstart

From the workstation (both drive the box over ssh):

```bash
scripts/deploy-racknerd.sh              # rsync + install unit + restart
scripts/platform-bootstrap.sh           # push the source mirror, then the 17-stage
                                        # Layer-0 bring-up. Add --no-deploy to skip
                                        # the rsync. Idempotent.
```

On the box, as `harness`:

```bash
ams check-host                          # every prerequisite, with the fix for each failure
ams ctl status                          # what is running, healthy, on which port
ams platform status                     # per-service stage, sha, last healthy commit
ams platform sync --only kvservice      # one tick by hand; the timer runs the same code
ams platform rollback kvservice         # to the record's prev_sha, or --to SHA
ams secret set commentservice DEEPSEEK_API_KEY < key.txt
systemctl reload ams-harness            # = ams ctl reload
systemctl list-timers 'ams-platform-*'  # sync every 60 s, backup daily 04:10 UTC
```
