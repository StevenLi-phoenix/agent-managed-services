# Service declaration (`service.toml`)

One TOML file per service, generated by the agent. Loaded and validated by
`ams.schema.load`; every violation raises `DeclError("<field.path>: <why>")`.

```toml
id = "web-app"                # ^[a-z][a-z0-9-]{0,31}$ ; also cgroup + dir name
name = "Web App"              # optional, display only
secrets = ["SVC_SECRET"]      # names only; values via `ams secret set <id> SVC_SECRET` (stdin)

[start]
argv = ["python", "-m", "http.server", "${PORT_main}"]   # list, never a shell string
workdir = "app"               # relative to the service root, or absolute; no ".."

[env]                         # values may use ${PORT_<name>}; PATH/HOME/AMS_*/PORT_*/UV_*/PNPM_*/BUN_* are reserved
DATABASE_URL = "sqlite:///db.sqlite"

[ports]                       # name -> port; 0 = harness allocates (>=1024, rootless)
main = 0
admin = 8081                  # fixed request; conflict is a load-time error in the allocator

[runtime]                     # dependency isolation; userns only isolates permissions
kind = "venv"                 # none | venv | uv | pnpm | bun | nix
python = "3.12"               # venv/uv only
# node = "22"                 # pnpm/bun only (pnpm: system or pnpm-managed node; bun: ignored)
requirements = "requirements.txt"   # venv/uv only, relative to workdir
# sync = true                # uv only: workdir is a uv project; `uv sync --frozen`, venv at <workdir>/.venv;
#                             # `packages` must be empty in sync mode (deps come from pyproject/uv.lock)
packages = ["uvicorn"]        # pip/uv specs (venv/uv) or npm specs (pnpm/bun); nix uses nix_packages
# Environments live on the XFS reflink store (/home/harness/store): python venvs,
# pnpm projects (package-import-method=clone) and bun projects (--backend=copyfile)
# all share blocks with the harness-owned caches, and each env is owned by its service.

[health]
kind = "http"                 # none | tcp | http | log
port = "main"                 # tcp/http: a name from [ports]
path = "/healthz"             # http only
# pattern = "Listening on"    # log only: regex over stdout/stderr marks ready
interval_s = 10
timeout_s = 5
start_period_s = 30

[stop]
signal = "SIGTERM"            # SIG* name; sent to the main pid
timeout_s = 10                # then cgroup.kill (isolated) / SIGKILL group (plain)

[limits]                      # written verbatim to the service cgroup
memory_max = "256M"           # -> memory.max (K/M/G/T suffix or bytes)
cpu_max = "50%"               # -> cpu.max "50000 100000" (percent of one CPU, may exceed 100%)
pids_max = 64                 # -> pids.max

[restart]
policy = "on-failure"         # always | on-failure | never
max_retries = 5               # consecutive failures before giving up = at most 5 starts (escalated)
backoff_s = 1
backoff_max_s = 60

[logging]
format = "auto"               # auto | level-prefix | json | plain
```

## Log severity (`[logging] format`)

Every line a service writes is classified before the policy sees it. A level the
process never printed cannot be recovered by any heuristic, so this hint tells
the harness how *this* service marks severity:

| value | what is read |
|---|---|
| `level-prefix` | a leading `LEVEL name:` token (`%(levelname)s %(name)s: %(message)s`), case-insensitive |
| `json` | `level` or `severity` from the line parsed as one JSON object (Caddy's `debug\|info\|warn\|error\|panic\|fatal` included) |
| `plain` | text heuristics only (`ERROR`, `Traceback`, `WARNING`, …) |
| `auto` (default) | level prefix, then JSON, then the heuristics |

A stated level always beats the message body: an `INFO` line whose text contains
the word `ERROR` stays INFO. A line that carries no level at all (a traceback
body, a framework banner printed before logging was configured) falls back to
the heuristics rather than being silently downgraded. Only `level`/`severity`
are ever read out of a JSON line; the rest of the object is data.

## Runtime contract for the service process

- Runs as inner uid/gid 1000 inside its own user namespace; host sees
  `100000 + block` (see `DECISIONS.md`). No capabilities, `no_new_privs` set.
- `HOME` = service root, `cwd` = `workdir`, `PATH` = runtime bin dirs +
  `/usr/local/bin:/usr/bin:/bin`. Nothing else from the harness environment.
- `PORT_<name>` is exported for every declared port; `${PORT_<name>}` is
  expanded in `argv` and `env` values.
- `AMS_SERVICE_ID` is exported.
- `AMS_DATA_DIR` = `<service root>/data`, created before every start, mode 0750
  and owned by the service uid. It is the **only** directory a service should
  treat as persistent: put databases, uploads and caches there. A re-provision
  rewrites the runtime and the source tree; `data/` is left alone. The harness
  uid cannot read it (that is the point), so anything that has to touch it from
  the outside — the backup job, for instance — goes through the admin
  namespace.
- stdout/stderr are pipes held by the harness. Lines longer than 64 KiB are
  truncated. Write logs to stderr; do not daemonize.
- The harness's own health probe is not noise: an access-log line for
  `health.path` from `127.0.0.1` answering 2xx/3xx is dropped by
  `DefaultPolicy` (`suppress_self_probes=False` turns that off). A 500 on the
  same path is kept.

## Secrets

`secrets` lists environment variable **names**, never values. The names are
validated like `[env]` keys (reserved names rejected) and may not also appear in
`[env]`; that collision is an error rather than a silent precedence rule.

The value is written once, out of band:

```sh
openssl rand -hex 32 | ams secret set web-app SVC_SECRET   # stdin, never argv
ams secret set web-app SVC_SECRET --from-file /path/to/value
ams secret list web-app        # names only
ams secret check web-app       # exit 1 listing declared names with no value
ams secret rm web-app SVC_SECRET
```

It lands in the harness-private store at `<state>/secrets/<id>/<NAME>`, mode
0600, owned by the harness user, and is injected into the service environment at
every start. The harness uid is deliberately absent from a service's uid map
(`DECISIONS.md` D4), so a service can read its own environment but not the file
the value came from — nor any other service's.

Exactly one trailing newline is stripped from the stored value, so
`echo secret | ams secret set ...` does what it looks like; a value that really
ends in a newline needs two. NUL bytes and empty values are rejected.

A declared secret with no stored value is **not** silently empty: the harness
logs a warning at startup and the service's start fails with an escalation until
the value is set. Nothing in `ams` ever prints, logs or reprs a value.
