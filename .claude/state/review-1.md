| **CRITICAL** | `supervisor.py:380-381` vs `538-546` | **100 % CPU for the whole `stop.timeout_s` window.** `_poll_timeout` folds in `monitor.next_due` whenever `st.spawned is not None`, but `_run_timers` only services that timer when `st.status in ("starting","running")`. `stop()` (l.236-239) sets `status="stopping"` and does **not** call `monitor.stop()` on the still-spawned branch, so an overdue health timer is never advanced → `poll_timeout==0` forever. | **HIGH** | `supervisor.py:190-193` | **`start()` on a running service silently orphans it.** The guard is `if st.spawned is not None: self._finalize(st, force=True)` with no `st.reaped` check. `_finalize` closes the fds, drops `_by_pid[old_pid]` and calls `spawner.cleanup` — but never kills. | **HIGH** | `spawn.py:109-111` | **4 fds leaked per failed spawn.** Both pipes are created *before* `req.workdir.mkdir(...)`, which is outside the `try`. Consequences: (a) `gid_start` is never checked, so a state file whose gid block does not correspond to the same index yields **overlapping gid blocks**; (b) a per-block `size` different from the file-level `block_size` passes `_load`'s guard and overlaps; (c) if `/etc/subuid`'s start moves, stored blocks map to bogus (even negative) indices and a new block can straddle an existing one (e.g. old start 100000, new 65536 → index 33 → 99328..100351 overlaps 100000..101023). | Compute free space by testing candidate `[start, start+size)` against the stored intervals (uid **and** gid), and validate on load that each block is inside a configured range and aligned; quarantine otherwise. | **Verified by arithmetic**, not executed; the `block_size`-change case asked about *is* correctly guarded by `_load` (l.122-129). |

## Verified OK

- **`spawner.cleanup` / fd + zombie hygiene on the normal path.** `_finalize` unregisters both fds (`supervisor.py:594-595`) *before* `cleanup` closes them, so no closed-fd stays in the selector; `_by_pid` is popped there too. `_reap` uses `waitpid(-1, WNOHANG)` in a loop, so no zombies, and non-service pids become `OrphanReaped` (`supervisor.py:460-464`).
- **Signal handling is sound.** Self-pipe with both ends non-blocking (`723-726`), `set_wakeup_fd` on a non-blocking writer, no-op handlers so no `KeyboardInterrupt` mid-loop, handlers/wakeup restored in `__exit__`. `select` order (poll → read → reap) means a SIGCHLD racing `_reap` still wakes the *next* poll — no lost wakeup. `run_forever` always passes `LOOP_TIMEOUT_S=0.25`, so there is **no hang** even with a pending stop deadline.
- **`os.read` error handling is correct** (`395-410`): `BlockingIOError` → return, `InterruptedError` → retry, `EBADF`/other `OSError` → treat as EOF, empty read → EOF; `_mark_eof` is idempotent and flushes the partial buffer. `_consume` caps the unterminated tail at `MAX_LINE_BYTES+1` so a service cannot exhaust harness memory with one endless line.
- **D11 restart/reset semantics match the record.** `health.kind="none"` does not reset the streak (`565`); only the `max(10, start_period_s)` running window (`480`, `533-537`) or a real probe success does. Terminal states are escalated by the supervisor independently of the policy (`_escalate_terminal`, `685-690`). `_schedule_restart`'s `exp = max(0, failures-1)` gives `backoff_s` on the first failure — no off-by-one there.
- **Ports Q3: the persisted table is consulted before any bind probe.** `_pick_free` seeds `taken` from `_ports_used_by_others` ∪ already-picked (`165-166`), so a *stopped* service's port is never handed out. A fixed request colliding with another service raises `PortConflict` **before** the bind probe (`145-155`), and `_save()` runs only after every check and every pick (`161-162`). Re-requesting one's own port skips the checks, so a restart cannot conflict with itself.
- **uidmap Q4: the `block_size`-change case is guarded.** `_load` refuses a state file written with a different `block_size` (`122-129`), so the release + re-allocate scenario asked about cannot produce overlap through that route. Alignment inside a stable range is exact (`ur.start + i*block_size`, bounded by `min(ur.count, gr.count)//block_size`). `release()` documents that host-side files outlive it.
- **CLI Q5: no silent fallback, and stdout is clean.** `_make_spawner` never falls back; `CgroupUnavailable`/`ImportError` are caught at `cli.py:128` and produce a named-fix message on **stderr** with `EXIT_UNAVAILABLE=2`. Every `print` in the `run` path targets stderr (`117`, `129`), logging is forced to stderr (`88-94`), and `JsonLinesEscalation` writes only compact one-object-per-line JSON to stdout — `json.dumps` escapes newlines and (default `ensure_ascii`) non-ASCII, so attacker-controlled log text cannot inject a fake escalation record.
- **Trust boundary generally.** No `shell=True` anywhere; `argv` is a tuple validated at load; `IsolatedSpawner` resolves the executable in the harness rather than in the namespace (`isolated.py:58-62`); severity classification only pattern-matches text and never interprets it; a policy or escalation raising cannot take down the loop (`624-628`, `692-696`).
